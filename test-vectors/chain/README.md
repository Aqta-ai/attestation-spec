# chain conformance vectors (DRAFT)

Deterministic vectors for the `chain` profile in [spec/USE-v1.md](../../spec/USE-v1.md)
section 9: a GRANT-v1 approval ([spec/GRANT-v1.md](../../spec/GRANT-v1.md)), the
USE-v1 records that consumed it, and the ACTION-v1 records they authorised,
checked together. Generated by [`generate.py`](./generate.py) from seeds under
`sha256("attestation-spec/test-vectors/chain-1/<label>")`. GRANT-v1 and USE-v1
are drafts and not frozen; these vectors move with them until they are.

Vector issuer public key (pin this as the issuer key):

    VZh1DjZPXa6voCmlv7MU7APjSr-HFxrG2WSqDm-eBGE

Each file is `{"approver_keys": [...] | null, "bundle": {...}}`. `approver_keys`
is the relying party's designated approver set for that vector; `null` means
the relying party supplied none. A conformant verifier, invoked explicitly with
the `chain` profile, the key above pinned and that approver set, MUST return:

| Directory | Verdict |
|---|---|
| `pass/` | `PASS` |
| `fail/` | `FAIL` |
| `incomplete/` | `INCOMPLETE` |

`INCOMPLETE` is never a pass. A verifier that collapses it into `PASS` fails
every vector in `incomplete/`; one that collapses it into `FAIL` fails them too.

What each vector pins is listed in [`INDEX.md`](./INDEX.md), generated with the
vectors. The design attacks A1 to A16 map onto them as follows: A1 fail/001-002;
A2 fail/003; A3 fail/004; A4 incomplete/001; A5 fail/005; A6 fail/006; A7
fail/007; A8 fail/008; A9 incomplete/002; A10 incomplete/003; A11 fail/009-011;
A12 fail/012; A13 fail/013; A14 fail/014; A15 fail/015; A16 (encodings: number,
number-like strings, escapes, padding, line feeds, non-BMP order) fail/021,
022, 027, 029, 030-032, 035 and pass/007-008. Every vector participates in the
cross-implementation interop sweep (`scripts/chain-interop-sweep.mjs`).

Every key here is a throwaway. None is a production key.
