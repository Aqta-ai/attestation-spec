# ACCEPT-v1 conformance vectors

Deterministic test vectors for [spec/ACCEPT-v1.md](../../spec/ACCEPT-v1.md),
generated by [`generate.py`](./generate.py) from the seed
`sha256("attestation-spec/test-vectors/accept-1")`.

Vector issuer public key (pin this when verifying the suite):

    j3Mkkm9t2FJCeuFwNfnFLJOQv_iqMit-2jLaiUuV8sE

A conformant ACCEPT-v1 verifier MUST return **valid: true** for every record
in `valid/` and **valid: false** for every record in `invalid/`, when invoked
explicitly for the ACCEPT-v1 profile with the key above pinned.

## valid/

| Vector | Exercises |
|---|---|
| 001-accepted | The reviewer adopted the machine's outcome. |
| 002-overridden-with-reason | Override with a committed `reason_hash`; the reason text is not in the record. |
| 003-escalated | Referred onward rather than decided. |
| 004-subject-is-an-action | The subject is an ACTION-v1 record, not a receipt (`subject_v` is `action-1`). |
| 005-no-reason | `reason_hash` is `""`, which is permitted. |
| 006-no-authority-stated | `reviewer_authority` is `""`, which is permitted. |
| 007-empty-policy | `policy_applied` is `[]`. |
| 008-non-ascii-reviewer | Non-ASCII in `reviewer_ref` and `reviewer_authority`, signed as literal UTF-8. |

## invalid/

| Vector | MUST fail because |
|---|---|
| 001-tampered-signature | Signature bytes altered after signing. |
| 002-tampered-decision | `decision` changed from ACCEPTED to OVERRIDDEN after signing. |
| 003-tampered-public-key | `public_key` replaced; also fails the pin check. |
| 004-missing-field | Required field `reviewer_authority` absent. Empty is allowed, absent is not. |
| 005-unknown-field | Carries `reviewer_name`. Unknown fields are rejected, and a plausible-looking one is the case worth pinning. |
| 006-integer-version | `v` is the integer `1`; ACCEPT-v1 requires the string `"accept-1"`. |
| 007-attestation-v1-receipt | A correctly signed ATTESTATION-v1 receipt. |
| 008-action-v1-record | A correctly signed ACTION-v1 record. Accepting either 007 or 008 means the verifier inferred the profile from field shape, which every spec in this family forbids. |
| 009-pack-verdict-as-decision | `decision` is `DECLINED`, which is a reviewer's verdict on an evidence pack: a different act, on a different subject, and not this record. |
| 010-unknown-subject-version | `subject_v` is `"2"`, a version this record cannot bind to. |
| 011-uppercase-subject-hash | `subject_hash` in uppercase hex; the format is 64 lowercase hex chars. |
| 012-empty-reviewer | `reviewer_ref` is `""`. The field is caller-asserted and never verified, but a record that names nobody at all is not an acceptance. |
| 013-policy-not-sorted | `policy_applied` reordered after signing. |
| 014-timestamp-no-offset | Timestamp lacks an explicit timezone offset. |
| 015-escaped-unicode-signing | Signed over `\uXXXX`-escaped bytes; a conformant verifier reconstructs literal UTF-8 and the signature fails. |

## What these vectors do not test

The **subject binding** (spec §6.1) is checked against a subject record the
verifier is separately given, so it cannot be exercised by a single-file
vector. A verifier that holds both records MUST report the binding result
separately from the signature result: a record can carry a valid signature
and a `subject_hash` that does not match the subject in hand, and those are
different failures meaning different things.

They also cannot test the reviewer. Nothing in this suite establishes that
`reviewer_ref` names a real person with the stated authority, because the
format does not establish it either (spec §8).

## Regenerating

Deterministic: same seed, same bytes. Treat any diff in existing vectors as a
breaking change requiring a version decision.
