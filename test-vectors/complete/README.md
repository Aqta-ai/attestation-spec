# complete conformance vectors (DRAFT)

Deterministic vectors for the `complete` profile in [spec/CHECKPOINT-v1.md](../../spec/CHECKPOINT-v1.md) section 8:
ACTION-v1 and USE-v1 records checked against the CHECKPOINT-v1 checkpoints that cover a review window, and
optionally reconciled against an executor's EXECUTION-v1 log ([spec/EXECUTION-v1.md](../../spec/EXECUTION-v1.md)).
Generated by [`scripts/make-e79-vectors.py`](../../scripts/make-e79-vectors.py) from public seeds. The formats are
drafts and these vectors move with them until they are frozen.

Each file is `{"review_from", "review_to", "executor_keys": [...] | null, "bundle": {...}}`. A conformant verifier,
invoked explicitly with the `complete` profile, the issuer key in [`INDEX.md`](./INDEX.md) pinned and those
parameters, MUST return `PASS` for `pass/`, `FAIL` for `fail/` and `INCOMPLETE` for `incomplete/`. INCOMPLETE is
never a pass.

What the vectors do not show: an issuer that never records a refusal which never reaches the executor passes. That is
the stated limit of the profile (ISSUER-ADVERSARY A2 is narrowed, not closed). Every vector participates in
`scripts/e79-interop-sweep.mjs`. Every key here is a throwaway.
